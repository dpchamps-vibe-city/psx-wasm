# M2 — Whole-game link and headless boot

**Status:** not started
**Depends on:** M1. **Unlocks:** M4, M6, M8 (and M3's whole-game oracle).
**Design refs:** design §3 (overlays), §5 (SDK layers), §6 (time), §7
(precompiled runtime), Runtime (boot, BIOS, clock, cd); decisions D7,
D12–D19.

## Goal

Link all of btn (every container, decompiled C plus translated code, plus
the precompiled runtime archive) into one `game.wasm`. Boot it headless
under wasmtime from the user's disc image, through the game's own entry
point, to its main loop.

The CD data path is real and verified. The other devices are stubs that
log and return plausible values.

## Context

- M1 delivers the translator, the linker core (harness mode), adapters,
  the dispatch table, the guest passes and prototype facts.
- M0 findings still open: 6 interior entries (`func_8001A940`…`A968`
  inside `func_8001A8D0`), 43 tentative-definition addresses, 32 variadic
  thunks.
- **btn specifics,** read from data, never hard-coded:
  - EXE load address and entry point come from the PS-X EXE header (btn's
    entry is `__start` at `0x80011278`);
  - 13 overlays in two slots (`0x800B7E20`, `0x8012DDE8`);
  - 690 calls from the EXE into overlays by absolute address;
  - btn reads its data through its own archive layer
    (`CdReadArchiveBytes` …) on top of libcd, which is guest code.
- The disc image is user-supplied (`psxw.local.toml`). Its track sha1 is
  pinned in `inputs.lock` the first time it's provided.

## Scope

**In**
- **Crate split:**
  - `psx-runtime`: boot, scheduler, guest memory, host interface, archive
    build;
  - `psx-bios`;
  - `psx-devices`: clock and cd now; gpu, spu and sio stubs;
  - `sdk-psyq`: adapters.
- **The runtime archive:** Rust `staticlib` for `wasm32-unknown-unknown`,
  built by `psxw runtime build`, ABI-versioned. The linker accepts Rust
  objects (more relocation kinds) and places Rust data, stack and heap at
  `RUNTIME_BASE` and above. Rust keeps table 0; the guest uses table 1.
- **Game-mode link:**
  - every container;
  - overlay dispatch stubs keyed on resident code;
  - EXE→overlay calls by absolute address;
  - interior entry stubs, where referenced;
  - the variadic thunks;
  - safepoints at loop headers;
  - the `untranslated` trap path;
  - a debug masking mode that traps on accesses to the I/O window.
- **Boot:** read `SYSTEM.CNF` from the disc, load the PS-X EXE, zero BSS,
  set `sp` (and `gp`), call the translated or C entry function at `pc0`.
- **BIOS dispatcher (A0/B0/C0 + `syscall`):**
  - implementations for the calls the game and SDK make;
  - a trap with `(table, fn)` for anything unimplemented;
  - the call list is generated by scanning the translator's output for
    BIOS call sites.
- **Clock and scheduler:**
  - virtual time in CPU cycles;
  - vblank cadence per psx-spx for NTSC and PAL, with the video mode from
    the game manifest or the disc region;
  - the four root counters;
  - the event queue and safepoint quantum;
  - callback delivery through `guest_invoke`.
- **libetc, libapi `counter.o`, and BIOS-event adapters:** `VSync`,
  `VSyncCallback`, `ResetCallback`, `InterruptCallback`, the
  `*RCnt` functions, and `OpenEvent`/`EnableEvent`/`TestEvent`/`WaitEvent`
  through the BIOS.
- **CD device and libcd data-path adapters:**
  - cue/bin (MODE2/2352) and iso (2048) images;
  - sector reads with EDC verification;
  - ISO9660 (`CdSearchFile`);
  - drive commands `Setloc`, `ReadN`, `ReadS` (data only; XA audio in M6),
    `Pause`, `Init`, `SetMode`, `Seek*`, `Getloc*`, `GetTN`/`GetTD`,
    `Nop`;
  - `CdRead`, `CdReadSync`, `CdReadCallback`, `CdReady`, `CdGetSector`,
    `CdSync`, `CdSyncCallback`, `CdControl*`;
  - the realistic/instant timing toggle (D19).
- **Stub adapters** for libgpu, libspu, libpad, libmcrd, libmcx and
  libcard, with logging and plausible results. Examples: `DrawSync`
  returns 0; `StoreImage` fills zeros; the pad reports no buttons; no
  memory card.
- **Host interface v1** in `psxw-abi` and **the wasmtime host**
  (`psxw-host-native`): `psxw run <game> --headless`, with replay input
  (empty replay = no input), RAM dumps and hashes per frame.
- **UBSan build variant** (`--ubsan`), whose trap handlers log the
  location.
- **The tier report:** `psxw report tiers <game>`.

**Out**
- real GPU, SPU and pad devices (M4/M6);
- XA (M6);
- memory cards (M7);
- the browser (M5);
- the oracle comparison against an emulator (M3, which needs M2's runs).

## Design details

### Host interface v1

`game.wasm` imports these from module `host`; all pointers are runtime
memory:

| Import | Purpose |
|---|---|
| `log(level, ptr, len)` | |
| `trap(code, ptr, len) -> !` | Fatal; carries a message |
| `wait_vblank(frame: u64)` | Pacing; headless returns immediately |
| `disc_info(out_ptr)` | Track list and sizes |
| `disc_read(lba, count, mode, dst_ptr) -> status` | `mode` is raw 2352 or user 2048 |
| `pad_state(port, out_ptr) -> len` | From the replay or live input |
| `storage_read(name_ptr, len, dst, cap) -> len` / `storage_write(...)` | Memory cards (M7) |

`game.wasm` exports `memory`, `psxw_abi_version`, `psxw_boot(options_ptr)`,
`psxw_run_frames(n) -> status`, and RAM and VRAM hash helpers for tests.

### Boot sequence

1. Read `SYSTEM.CNF` through the CD device's ISO9660 (`BOOT=`, `TCB`,
   `EVENT`, `STACK`).
2. Load the PS-X EXE: header fields `pc0`, `gp0`, `t_addr`, `t_size`,
   `b_addr`, `b_size`, `s_addr`, `s_size`. Copy text and data into the
   window.
3. Zero BSS if `b_size` is set.
4. Set `sp` to `s_addr + s_size`, or the BIOS default.
5. Call the function at `pc0` through the dispatch table. When `main`
   returns, the BIOS would idle: log and stop.

### Overlay dispatch

- **A stub per overlay address.** For each address that more than one
  container defines, and for every overlay function referenced from
  outside its overlay (absolute calls from the EXE, table entries), the
  stub:
  1. reads 2 code words at the address in guest RAM;
  2. compares them with each candidate container's original words at that
     address;
  3. calls the matching container's function;
  4. if none match, traps `no translation for resident code at ADDR`, with
     the words found.
- **Calls inside an overlay** are direct.
- **Debug mode** also verifies, on first dispatch per load, that the whole
  resident overlay region equals that container's image (sha1 from splat).

### Safepoints

- **A budget check at every loop header** of guest functions:
  `global $budget` is decremented; at zero, `psxw_safepoint()` is called.
- **`psxw_safepoint`** advances virtual time by the quantum, delivers due
  events, and resets the budget.
- **The quantum and budget are runtime options.** Defaults are tuned so
  that a spin-wait on a vblank flag converges in a bounded number of host
  iterations.

## Exit criteria (all automated)

1. **Build.** `psxw build btn` produces `out/btn/game.wasm`, which passes
   validation and the ABI version check, linking the precompiled runtime
   archive.
2. **Boot.** `psxw run btn --headless --frames 600 --check boot` passes:
   - RAM over `[t_addr, t_addr + t_size)` equals the EXE image right after
     load;
   - every CD sector read passes EDC, and the disc track sha1 matches
     `inputs.lock`;
   - every overlay load leaves resident bytes equal to that container's
     image (debug mode), and every overlay dispatch finds a match;
   - no `untranslated`, BIOS-unimplemented or I/O-window trap;
   - at least 600 VSync waits completed, and the manifest's
     `main_loop_symbol` (a function address, game-specific, in
     `game.toml`) has been entered.
3. **Determinism.** RAM hashes at frames 60, 300 and 600 are identical
   across two runs.
4. **UBSan.** No unexplained reports along the boot path.
5. **`psxw ci btn`** includes all of the above.

## Risks and decision points

- **Rust staticlib relocations** may include kinds the M1 reader doesn't
  handle. Extend it, test it, and keep a list.
- **Callback re-entrancy.** The runtime must not hold borrows across
  `guest_invoke`. Structure state as cells with short borrows; add a debug
  assertion.
- **Games that spin on hardware status without a runtime call** rely on
  the safepoint quantum. Tune the default and record it.
- **Unknown BIOS calls** trap with clear ids. Implement them from psx-spx
  semantics. The BIOS oracle comes with M3: device-target BIOS vectors.
